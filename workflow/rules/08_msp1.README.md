# 08_msp1 — MSP1 as a candidate third marker

Stages MSP1 reference data, an in-silico cross-species PCR check against the Swangsri et al. 2025 primers, and a full-gene alignment/entropy/primer-candidate pipeline that mirrors the existing MIT and 18S rules.

## Three deliverables

1. **`scripts/python/fetch_msp1_refs.py`** — pulls MSP1 GenBank records for the 11 panel species via NCBI E-utilities. Writes one FASTA per species into `data/reference/msp1/`, a concatenated `msp1_ref_db.fasta`, and a `fetch_log.tsv`. Normalises FASTA headers through the project's `case_when` species convention. Must be run from a machine with NCBI access — the analysis sandbox proxy blocks `eutils.ncbi.nlm.nih.gov` (403).
2. **`scripts/R/msp1_amplicon_specificity.R`** — amplicon-level question. Takes Swangsri's three primer pairs (Pk, Pcy, Pin), runs in-silico PCR against all 11 species' MSP1 references, reports per-species fwd/rev match status, mismatches, predicted amplicon length, and a Wallace-rule Tm proxy. Answers "can the Swangsri qPCR/melt assay extend to other species, or do the primers fail / mis-prime?".
3. **`workflow/rules/08_msp1.smk`** — full-gene MSP1 marker pipeline. Mirrors the MIT/18S rule shapes in `03_alignment.smk`: subset → MAFFT → entropy → primer-candidate windows → plots. Adds an `msp1_all` convenience target.

## Why two scopes (amplicon and full-gene)

- The **amplicon-level** analysis validates or invalidates the Swangsri 2025 assay's species coverage claims against species they didn't test. Useful immediately for the colleagues replicating the Swangsri assay — does it actually amplify cleanly against, say, *P. coatneyi* (a known near-neighbour of knowlesi), or does it cross-react?
- The **full-gene** analysis answers a different question: should MSP1 join MIT and 18S as a third marker in the long-read panel? That requires the same entropy / per-pair similarity / cross-marker resolution treatment as Chapters 4–5 give MIT and 18S. The Snakemake rule file reuses the same scripts (`align.sh`, `seq_entropy.py`, `plot_entropy.R`) with `marker="msp1"`, so once it runs, the existing Chapter 5 resolution-table machinery can be extended trivially.

The amplicon question runs in seconds once references are fetched; the full-gene question is a real analytical pass and lands a new chapter's worth of figures.

## How to run

```bash
# 1. Fetch (from a machine with NCBI access)
python3 scripts/python/fetch_msp1_refs.py \
    --outdir data/reference/msp1 \
    --max-seqs 20

# 2. Amplicon-level Swangsri primer check
Rscript scripts/R/msp1_amplicon_specificity.R \
    --refdir data/reference/msp1 \
    --out    outputs/msp1/amplicon_specificity.tsv

# 3. Full-gene marker pipeline (Snakemake)
#    (After adding "workflow/rules/08_msp1.smk" to the include list in
#    the main Snakefile.)
snakemake --snakefile workflow/Snakefile --cores 4 msp1_all
```

## Hand-off notes for Claude Code

- The `subset_to_targets.sh` flag pattern is identical to 18S (`-n -i`) because MSP1 references will come out of the fetch with descriptive (not encoded) headers.
- The `seq_entropy.py` `end_region` constraint that bit the published Imwong 18S primers (see `06_entropy_audit.README.md`) will apply identically to MSP1 — interior candidate windows will be `end_region = "none"`. If the goal is to compare against an interior region of MSP1 (which is where the Swangsri primers actually sit at positions ~600–820), the same "lift the end-region constraint" path discussed in `06_entropy_audit.README.md` applies. Worth deciding upfront.
- Per-species coverage will be uneven. *P. simiovale* and *P. fieldi* have very limited MSP1 records on GenBank as of 2026; expect 0–3 sequences each. The fetch log surfaces this. Some species may need manual curation of partial sequences or hybrid references.
- Header convention to follow the rest of the panel: `>ACCESSION.V Pspecies msp1 | <original description>`. The fetch script writes this format; the R amplicon script and the Snakemake rules both read it.
